═══════════════════════════════════════════════════════════════════════
 PICO · GUÍA DE FIREBASE — Rol de administrador real (custom claims)
═══════════════════════════════════════════════════════════════════════

Hay 3 cosas independientes que configurar. Hazlas en este orden:

  1) REGLAS de Firestore     → en la CONSOLA web (sin comandos)
  2) La FUNCIÓN setAdminRole  → 1 sola vez por línea de comandos (Windows)
  3) AGREGAR admins           → desde la propia página de PICO (sin comandos)

El rol "admin" vive como CUSTOM CLAIM dentro del token del usuario
(admin === true). Es la fuente de verdad y las reglas lo verifican con
request.auth.token.admin == true. No cuesta lecturas: viaja en el token.


═══════════════════════════════════════════════════════════════════════
 1) REGLAS DE FIRESTORE  (cópialas COMPLETAS y pégalas en la consola)
═══════════════════════════════════════════════════════════════════════
 Consola de Firebase → Firestore Database → pestaña "Reglas" (Rules) →
 borra todo → pega esto → botón "Publicar" (Publish).

 ✅ Ya corregí el problema de la factura: tu regla vieja de 'mail' solo
    dejaba enviar a picosvsupport, y la FACTURA va al correo del cliente.
 ✅ Endurecí lo que solo el admin debe tocar, SIN romper pedidos:
    - productos: el cliente solo puede cambiar el STOCK (al pedir/cancelar);
      precio, costo, descripción, categoría y orden son solo de admin.
    - estadisticas: el cliente solo mueve los contadores de pendientes/
      cancelados; el resto (ventas, ingresos, costos) es solo de admin.
    - ventas, gastos, restock, etc.: solo admin.

-----------------------------------------------------------------------
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // ¿El usuario es administrador? (custom claim en el token)
    function isAdmin() {
      return request.auth != null && request.auth.token.admin == true;
    }

    // Catálogo: lectura pública. Escritura: admin para todo; un usuario
    // autenticado SOLO puede tocar el stock (al crear o cancelar un pedido).
    match /productos/{id} {
      allow read: if true;
      allow create, delete: if isAdmin();
      allow update: if isAdmin()
        || (request.auth != null
            && request.resource.data.diff(resource.data).affectedKeys()
                 .hasOnly(['stockCdb','stockExsal','updatedAt']));
    }

    // Pedidos: el cliente crea/cancela el suyo; el admin gestiona todos.
    match /pedidos/{id} {
      allow read, write: if request.auth != null;
    }

    // Facturas: el cliente crea/actualiza la suya; el admin las gestiona.
    match /facturas/{id} {
      allow read, write: if request.auth != null;
    }

    // Estadísticas: admin para todo. Un cliente solo puede mover los
    // contadores de pedidos pendientes/cancelados (al pedir o cancelar).
    match /estadisticas/{id} {
      allow read: if request.auth != null;
      allow write: if isAdmin()
        || (request.auth != null
            && request.resource.data.diff(resource.data).affectedKeys()
                 .hasOnly(['pedidosPendientes','pedidosCancelados']));
    }

    // Descuentos: los clientes los LEEN para aplicarlos; solo admin los crea.
    match /descuentos/{id} {
      allow read: if request.auth != null;
      allow write: if isAdmin();
    }

    // Descuentos asignados a cada cliente: el cliente lee el suyo; admin asigna.
    match /user-discounts/{uid} {
      allow read: if isAdmin() || (request.auth != null && request.auth.uid == uid);
      allow write: if isAdmin();
    }

    // Perfiles de cliente (cross-device): cada quien gestiona el suyo.
    match /perfiles/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

    // Lista maestra de categorías: la lee la tienda; solo admin la edita.
    match /config/categorias {
      allow read: if true;
      allow write: if isAdmin();
    }

    // Administradores (espejo solo para listarlos en el panel).
    // Lo ESCRIBE únicamente la Cloud Function (Admin SDK, ignora reglas).
    match /admins/{uid} {
      allow read: if isAdmin();
      allow write: if false;
    }

    // ── Colecciones SOLO de gestión (inventario) → solo admin ──
    match /ventas/{id}                 { allow read, write: if isAdmin(); }
    match /ventas-eliminadas/{id}      { allow read, write: if isAdmin(); }
    match /restock-historial/{id}      { allow read, write: if isAdmin(); }
    match /estadisticas-historial/{id} { allow read, write: if isAdmin(); }
    match /gastos/{id}                 { allow read, write: if isAdmin(); }

    // Correo (extensión Trigger Email): avisos a soporte o la FACTURA al
    // propio correo del cliente. Nadie puede leer/editar/borrar la cola.
    match /mail/{id} {
      allow create: if request.resource.data.to == 'picosvsupport@gmail.com'
        || (request.auth != null && request.resource.data.to == request.auth.token.email);
      allow read, update, delete: if false;
    }
  }
}

═══════════════════════════════════════════════════════════════════════
 2) DESPLEGAR LA FUNCIÓN  setAdminRole   (Windows · una sola vez)
═══════════════════════════════════════════════════════════════════════
 Esto es lo que crea/quita el rol de verdad. Ya usas Cloud Functions
 (Wompi), así que es el mismo procedimiento.

 PASO A — Pon tu correo para poder crear el PRIMER admin:
   Abre  functions/index.js  y busca BOOTSTRAP_ADMINS (casi al final).
   Déjalo así (con TU correo, el que usarás para entrar a PICO):

       const BOOTSTRAP_ADMINS = [ 'tucorreo@ejemplo.com' ];

 PASO B — Abre PowerShell o CMD en la carpeta del proyecto (la que tiene
   firebase.json). Truco: abre la carpeta en el Explorador de Windows,
   escribe  cmd  en la barra de direcciones y Enter.

 PASO C — Si nunca instalaste la CLI de Firebase en esta PC:
       npm install -g firebase-tools
       firebase login        (se abre el navegador para iniciar sesión)

 PASO D — Despliega SOLO esta función:
       firebase deploy --only functions:setAdminRole

   (Si te pide elegir proyecto:  firebase use pico-6c040  y repite.)


═══════════════════════════════════════════════════════════════════════
 3) CREAR/AGREGAR ADMINISTRADORES   (desde la web, sin comandos)
═══════════════════════════════════════════════════════════════════════

 PRIMER admin (tú):
   a) Inicia sesión en PICO con el correo que pusiste en BOOTSTRAP_ADMINS
      (debe existir como usuario: entra una vez con Google o regístrate).
   b) Ve a  📊 Admin → tarjeta "🛡️ Administradores".
   c) Escribe tu correo y pulsa "Hacer admin". Como estás en la lista de
      bootstrap, te dejará aunque todavía no seas admin.
   d) Tu token se refresca solo. Si el botón 📊 Admin no aparece enseguida,
      cierra sesión y vuelve a entrar.

 SIGUIENTES admins (ya sin comandos ni bootstrap):
   - Desde esa misma tarjeta "🛡️ Administradores", escribe el correo de la
     persona y pulsa "Hacer admin" (o "Quitar admin").
   - Esa persona debe haber iniciado sesión en PICO al menos una vez.
   - El cambio le aplica la próxima vez que inicie sesión.

 (Opcional, recomendado al terminar) Cierra la puerta del bootstrap:
   vacía  BOOTSTRAP_ADMINS = [];  y vuelve a desplegar (paso 2-D).


═══════════════════════════════════════════════════════════════════════
 NOTAS
═══════════════════════════════════════════════════════════════════════
 • Las REGLAS y la FUNCIÓN son cosas distintas: las reglas vigilan quién
   puede leer/escribir; la función pone el sello "admin" en el token.
   Necesitas las dos.
 • El inventario ahora SOLO deja entrar a admins reales. Si entras con una
   cuenta sin el rol, te saca con un aviso.
 • Si cambias el rol de OTRA persona, le aplica cuando vuelva a iniciar
   sesión (su token se renueva). Para ti mismo, la app lo refresca al toque.
